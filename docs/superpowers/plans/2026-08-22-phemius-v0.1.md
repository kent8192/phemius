# Phemius v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish the complete Phemius v0.1 macOS novel-writing agent harness defined by the approved specification.

**Architecture:** One Rust binary crate owns a deterministic controller around file-based canon, candidates, session events, source receipts, a thin OpenRouter SSE client, and a macOS Seatbelt shell boundary. Modules expose concrete data types and functions; the only alternate runtime backend is a scripted model used by evaluation and tests.

**Tech Stack:** Rust 2024, MSRV 1.89, Tokio, reqwest, Serde, clap, YAML/TOML/JSONL, macOS Seatbelt, Markdown canon.

**Spec:** `docs/superpowers/specs/2026-08-22-phemius-v0.1.md`

## Global Constraints

- One crate and one `phemius` binary; no workspace, service split, database, vector database, general DAG, provider SDK, or executable plugin SDK.
- Production code is written only after its focused test has been run and failed for the expected missing behavior.
- Code comments and public API documentation are English.
- Canon is UTF-8 Markdown with YAML frontmatter; unchanged body bytes and unknown YAML keys are preserved.
- Models produce candidates only; `/approve` remains a trusted REPL-only operation.
- Git is optional at runtime and is never mutated without an explicit human command.
- No automatic network retry, provider fallback, context compression, approval, model fallback, or sandbox downgrade.
- `OPENROUTER_API_KEY` remains in the trusted HTTP client and never enters child environments, logs, receipts, or argv.
- All durable file writes use explicit hashes and crash-safe ordering; security and cost boundaries fail closed.
- v0.1 targets Apple silicon macOS and ships source installation plus GitHub Release binaries.
