# Phemius v0.1 Design Specification

## Product

Phemius is a macOS-first, local Rust CLI for planning, drafting, reviewing,
revising, and approving long-form prose fiction. It uses OpenRouter-hosted
models while keeping the project canon in human-editable UTF-8 Markdown.

The primary acceptance scenario is one work containing 10-12 chapters of
8,000-12,000 Japanese grapheme clusters each, backed by up to 500,000
characters across 100 source files. The harness must detect character,
causality, setting, timeline, and foreshadowing contradictions; surface prose
quality findings; and prove that human corrections and registered sources
were carried into later generation contexts.

The repository and binary are both named `phemius`. The project is MIT
licensed and targets Apple silicon macOS. Source installation and GitHub
Release binaries are supported; crates.io, Homebrew, Intel macOS, OCR, and a
plugin SDK are outside v0.1.

## Architecture

Phemius is one binary crate with three logical boundaries:

- Session is the durable append-only event truth plus derived checkpoints.
- Harness is the deterministic controller, context compiler, workflow, and
  approval boundary.
- Sandbox is the child-process boundary used for model-requested shell work.

There is no JSON-RPC service, database, vector database, general DAG engine,
provider SDK, or executable plugin system in v0.1. Agent roles are data passed
to one shared execution loop. Tools are a fixed ordered enum dispatched by a
single match.

## Project and Canon

One project contains one work. The artifact hierarchy is:

`Work -> Part -> Chapter -> Scene -> micro beat/box`.

Macro structural beats are a separate layer and may link to multiple scenes.
Built-in structure definitions cover Save the Cat, three-act structure,
kishotenketsu, and flexible hakogaki. Project-local declarative definitions
may replace or combine them. Hakogaki is treated as a flexible scene-planning
method, not a fixed universal beat sequence.

The default tree is:

```text
project.toml
AGENTS.md
前提/
  作品.md
  キャラクター設定/<character>.md
  世界観設定.md
  時系列.md
  伏線.md
  文章スタイル.md
  執筆ルール.md
箱書き/
  構成.md
  章/<chapter>.md
  構成法/<custom-framework>.md
本文/<chapter>.md
メモ/
資料/
  manifest.md
  snapshots/
.phemius/
  records/<run-id>/...
  local.toml
  runtime/...
```

Canon artifacts are Markdown with YAML frontmatter. IDs use a semantic prefix
and UUID v7 (`work_`, `part_`, `chapter_`, `scene_`, `box_`, `character_`,
`source_`). Ordering is an explicit integer, not a filename or UUID sort.
Chapter manuscripts remain one file per chapter and contain invisible HTML
comments marking scene boundaries. One character has one Markdown file.
Unknown frontmatter keys and unchanged body bytes are preserved.

`.phemius/records` is tracked. `.phemius/local.toml` and
`.phemius/runtime` are ignored. Git is optional: Phemius provides its own
hashing, diffs, journal, and recovery. It never stages or commits without an
explicit human command.

## Candidate and Approval Contract

Models never write canon. Every proposed edit is a whole-file operation in a
changeset with before and after hashes, affected entity IDs, dependency
hashes, and a candidate path. A chapter changeset atomically groups its
manuscript, character updates, timeline updates, foreshadowing updates,
context receipt, critique summary, and basis record.

Changesets are all-or-nothing. Candidate files may be edited in an external
editor; any candidate hash change invalidates its critiques and near-copy
scan and makes descendant candidates stale. Canon edits made outside Phemius
freeze active work until the human adopts or reverts the detected diff.

`/approve <changeset-id>` is parsed only by the trusted REPL and is never an
LLM tool. Approval rechecks base hashes, schemas, blocker state, dependency
order, and validation hashes. A journal, before images, fsync, per-file atomic
rename, rollback, and startup recovery provide crash-recoverable logical
atomicity. Simultaneous visibility to unrelated external readers is not
promised.

Unresolved blockers cannot be waived. A human may classify an individual
finding as a false positive with `/resolve <finding-id> false-positive
<reason>`. Intentional story contradictions are resolved by updating the
canon or plot rather than bypassing the validator.

Continuous generation uses earlier unapproved chapter changesets as run-local
provisional canon. Approval remains chapter ordered. If an upstream chapter
is edited or rejected, unapproved descendants become stale. They may return
through explicit regeneration or a complete critic revalidation. Approved
descendants remain canon but become `needs-revalidation`; new generation and
approval stop until revalidation completes.

## Sources and Context Receipts

All content used as reference data is registered in `資料/manifest.md` with a
stable source ID, kind, scope, tier, and expected hash. Scope may be work,
part, chapter, scene, or agent role. The default tier is compactable. Required
sources cannot be excluded. Tier or scope changes are candidates requiring
human approval.

Every context receipt enumerates every applicable manifest entry exactly once
as `raw`, `compacted`, or `excluded`, including hash, ranges, reason,
truncation, and failure data. Pinned canon, the active box, recent prose,
human corrections, and raw-required sources are inserted verbatim. Older
chapters and general references may use hash-bound, source-anchored derived
summaries. Retrieval ranking may add recall but may never exclude mandatory
documents or decide receipt coverage. Embeddings are deferred until a measured
recall failure justifies them.

If mandatory raw context plus fixed instructions, tool schemas, recent tail,
and requested output reserve cannot fit the selected model, generation stops.
The guarantee is operational: Phemius proves hashes, ranges, context
injection, correction directives, and output validation. It does not claim to
prove a model's internal understanding.

Markdown, plain text, text PDFs, and Web pages are supported. PDF extraction
checks every page and stops with `ocr_required` for scanned, empty, encrypted,
or unextractable documents. Web retrieval stores raw bytes, final URL,
redirect chain, headers, timestamp, conversion version, and hashes. Web search
uses OpenRouter's server tool only in a discovery call; cited URLs are fetched,
snapshotted, and registered before manuscript generation.

An agent may request any local path. The trusted harness resolves and inspects
it before model exposure. A human grants one normalized file or fixed
directory snapshot for the current session. Changed files, new directory
entries, and symlink escapes require new approval. Secrets require a second
one-time confirmation and are neither written to session artifacts nor to the
event log; only their hash and transmission fact are recorded.

## Agent Workflow and Quality Gates

The fixed chapter workflow is:

`Story Architect -> Writer -> independent critics -> Reviser -> validators`.

Writer and Reviser run sequentially. Up to three critics run concurrently and
receive immutable, role-specific context. Roles are:

- character and voice;
- canon, causality, timeline, and foreshadowing;
- reader pull;
- story editing;
- naturalness, language, and style;
- source adherence.

Critics report typed findings with stable artifact ranges. The controller
sorts and aggregates them before revision. At most two revision cycles run,
and only failing critics rerun.

Unreferenced required sources, explicit canon contradictions, causal or
timeline breaks, and clear source imitation are blockers. Character, style,
and reader-pull judgments are advisory unless a deterministic contract is
also violated.

Near-copy detection blocks normalized contiguous matches of at least 80 CJK
grapheme clusters or 40 whitespace-delimited words. It also blocks at least
85 percent character 8-gram overlap over windows of at least 160 graphemes or
80 words. Project configuration may tighten or loosen these thresholds.
Declared quotations, licensed material, and the author's own registered text
may be exempted by explicit source ranges.

Human micro-edits can be promoted into scoped rules for one location, one
character, the current scene, the current chapter, the project, or an explicit
expiry. Approved rules and their hashes are mandatory context for affected
later chapters.

## Model Runtime

The initial model is `deepseek/deepseek-v4-pro-0813`. OpenRouter Chat
Completions is implemented directly with one pooled reqwest client and SSE
parsing. The client disables transport retries and redirects. Requests disable
provider fallback and context compression, require requested parameters, send
no fallback model array, and request router metadata.

SSE completion requires `[DONE]`. Text deltas and indexed tool-call deltas are
assembled before any tool arguments are parsed and validated. EOF, transport
failure, malformed JSON, or an error event before `[DONE]` produces an
ambiguous stopped state and never an automatic resend. Structured-output
validation may retry the same model at most twice, subject to the cost budget.

On a provider failure, the trusted UI offers: retry the same route, permit
same-model provider fallback for one request, switch model, or stop. Context
compression remains disabled. The actual model, provider, routing metadata,
usage, and cost are recorded.

`/model`, `/model <id>`, `/model <role> <id>`, and per-command overrides are
supported. Saving a default is explicit. Precedence is command, session,
project, user, built-in. A model change creates a new context epoch from the
latest checkpoint and recent tail without starting a new session.

## Session, Compaction, and Cost

The durable session is typed append-only JSONL. Checkpoints are derived and
atomically replaced. Only a crash-truncated final JSONL line may be repaired;
interior corruption stops recovery.

Context is a projection, not session truth. Automatic compaction triggers
when the conservative estimated next input exceeds model context minus the
larger of requested output and 20,000 tokens. It creates a structured rolling
summary and retains a 15,000-token raw tail. Old durable events remain.
Compaction failure is non-destructive. Canon, source facts, corrections,
blockers, stale state, and cost remain typed checkpoint data rather than
lossy prose summary.

Each agent invocation stops after 64 tool calls, checkpoints, and asks the
human whether to continue. Model-visible tool output is capped at 10,000
estimated tokens; complete output is stored as a content-addressed local
artifact. Local limits are 100 MiB per tool result and 2 GiB per session.
Referenced artifacts are protected from `/clean`.

The budget warns once before the first call expected to take a chapter over
$5, blocks before a chapter exceeds $10, and blocks before a continuous run
exceeds $120. A top-level run owns the budgets. Writing, critics, revision,
validation retries, and compaction are charged to the active chapter and run;
chapterless preparation is charged to the run. Each request reserves its
maximum estimated cost atomically before launch. Unknown prices stop. An
ambiguous response without usage retains its reservation as provisional cost.

## CLI and Sandbox

Top-level commands are `phemius init [PATH]`, `phemius [PROJECT]`, and
`phemius eval`. Init creates the minimal tree and conducts an interview whose
answers become an initial candidate changeset.

The REPL starts in `work` mode; `consult` is read-only. Commands include
`/help`, `/status`, `/mode`, `/plan`, `/write`, `/review`, `/revise`, `/diff`,
`/approve`, `/reject`, `/resolve`, `/model`, `/cost`, `/compact`, `/resume`,
`/skills`, `/clean`, and `/quit`. Natural language is mapped into the same
typed workflows, but approval, cleanup, persistent model settings, and
unrestricted execution cannot be triggered through model output or natural
language. `$skill-name` selects a skill explicitly.

Shell execution normally requires human approval for each command and runs
under macOS Seatbelt with network denied. Direct execution uses an absolute
program plus argv; shell syntax requires an explicit `/bin/zsh -lc` path.
Children receive a cleared environment with only non-secret values, a bounded
working directory, output and time limits, and no OpenRouter key. Critics
never receive shell access. Unrestricted mode removes approval and sandboxing
only after a trusted human action and is never persisted.

If Seatbelt initialization fails, the trusted UI offers: continue without
shell, enter unrestricted mode for the session, or stop. It never silently
downgrades. Built-in Web access remains a trusted harness tool.

Instructions follow hierarchical `AGENTS.md`. `CLAUDE.md` is a fallback only
when no applicable `AGENTS.md` exists. Skills are discovered from project
`.agents/skills`, configured directories, and user directories, in that
precedence. Startup loads metadata only; selection loads the complete
`SKILL.md`; referenced instructions, scripts, and templates load on demand.
Hashes of loaded skill resources appear in the context receipt. Skills extend
prompts and workflows but do not load executable code.

## Evaluation

`phemius eval` separates task, trial, trajectory, outcome, grader, and report.
Results are `pass`, `fail`, or `inconclusive`; API failures and judge
disagreement are not counted as prose failures. Hidden expectations are not
placed in the trial sandbox or agent context.

Deterministic gates cover hierarchy, IDs, length, canon immutability,
changeset recovery, source receipt coverage, planted contradictions,
near-copy stopping, human-correction propagation, stale behavior, and cost
boundaries. Cheap regression cases run three trials and require all three to
pass. A manual release evaluation runs one full 500,000-character, 100-source,
10-12-chapter trial after displaying and confirming the estimated cost.

Subjective evaluation compares a candidate blindly against a human-approved
baseline for character, causality, setting, reader pull, and style as separate
dimensions. A judge from a different model family evaluates both A/B orders
and cites stable ranges. Disagreement is inconclusive. Subjective results stay
advisory until at least 20 human blind labels reach 80 percent agreement and
90 percent swap consistency.
